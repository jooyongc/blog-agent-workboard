## 근본 원인

1. **복구 카운터 공유.** 답변 미완결 복구가 `payload.response_retries` 하나를 작업 전체에서 공유했습니다. 상위 검토가 한 번 쓰면 이후 보완 에이전트가 같은 문제로 멈췄습니다(`35cde761` 등).
2. **같은 출력 한도로 반복.** 복구 실행이 원래 `max_tokens`를 그대로 써서 잘린 답변이 다시 잘렸습니다.
3. **역할별 누락.** 형식 오류 복구는 supervisor/editor만, 미완결 복구는 researcher/supervisor/editor만 대상이었습니다. verifier와 writer의 형식 오류는 곧바로 중단됐습니다.
4. **메시지 문자열 기반 복구.** 복구 조건이 오류 문장 일부와 일회성 플래그(`grounding_recovery_v3`, `flash36_transition`, `flash31_transition`)로 흩어져 있었습니다. 세 플래그가 한 번의 복구에서 함께 소비돼 실제로는 1회만 동작했습니다.
5. **두 번째 추가 조사 요청이 하드 스톱.** 상위 검토가 추가 조사를 다시 요청하거나 마지막 라운드에서 요청하면 작업이 "추가 근거 또는 연결 설정 필요"로 멈췄습니다(`bffdf735`).
6. **리스 만료 정리 누락.** 리스가 만료되면 워크플로만 `interrupted`가 되고 단계 기록은 `running`으로 남았습니다(`f3af83f5`). 비용 예약도 `running`으로 남았고, 큐 체인은 다음 cron까지 멈췄습니다.

## 조치

`docs/AGENT-HARNESS.md`의 "Failure recovery policy"에 정리했습니다. 자동 반복은 역할·라운드별 1회로 유지하고, 재실행 때 출력 한도를 두 배(최대 16k)로 늘립니다. 비용이 불명확한 요청과 전송·이미지 단계는 반복하지 않습니다. 리스 만료 단계는 정리만 하고 재개는 사람이 확인 후 진행합니다.

독립 검토에서 지적된 다섯 가지를 반영했습니다.

- 비용 확인을 최신 기록 한 건이 아니라 해당 역할 시작 이후의 모든 호출로 넓혔습니다.
- 운영자가 수정한 초안은 자동 재개하지 않습니다.
- 이전 정책에서 이미 쓴 재시도 플래그를 존중하고, 자동 재개 기록을 남깁니다.
- 리스 정리 범위를 만료된 리스 이전 기록으로 한정했습니다.
- 추가 조사 전환 문구를 상황에 맞게 고치고, 삭제할 주장이 없으면 전환하지 않습니다.

리스 중 큐 체인을 유지하는 분기는 이득이 작아 제거했습니다.

배포 시점에 Cloudflare 소유 사이트에서 실패·대기 중인 워크플로는 없었습니다. 따라서 이번 배포가 기존 작업에 추가 비용을 즉시 발생시키지 않습니다. Korea Buy List(Aside 소유)의 실패 작업 `35cde761`은 복구 대상에서 명시적으로 제외했습니다.
