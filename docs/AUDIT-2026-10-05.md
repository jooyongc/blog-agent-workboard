# 2026-10-05 전체 점검 기록

## 확인하고 수정한 문제

1. 존재하지 않는 CloudStorage 작업 경로. 실제 코드 위치를 확인하고 사용자 승인으로 GitHub 저장소를 선택했다.
2. dry-run이 주제 상태를 바꾸고 유료 글 생성을 실행하던 문제. 현재는 GET preflight만 수행한다.
3. 게시물 조회 실패를 빈 목록으로 취급해 중복 생성할 위험. 실패 시 중단한다.
4. 주제 PATCH와 enqueue HTTP 오류를 무시하던 문제. 실패를 전파한다.
5. 일부 주제 실패가 실행 성공으로 보고되던 문제. 하나라도 실패하면 비정상 종료한다.
6. 단계 사이에 site 설정이 누락되고 고정 ASTY 경로를 사용하던 문제. 새 native bridge와 ASTY 파이프라인을 분리하고 잘못된 대상 실행은 차단한다.
7. 검증 보고서 누락/blocked 상태가 publish로 흘러가던 문제. 보고서와 현재 초안의 승인 hash를 확인한다.
8. 외부 조회 없는 모델 평가를 verified로 취급하던 문제. tool-free 평가를 partial로 낮추고 사람 검토가 필요하다.
9. publish_at의 서버 시간대 의존. KST 일자 기준 계산과 2시간 예약 제한을 적용한다.
10. 사이트명/slug 경로 순회, 잘못된 CLI 옵션, NaN limit, metadata slug 불일치. 입력 검증을 추가했다.
11. DeepL 언어 코드 표기 불일치와 비일본어 출력도 lang=ja가 되던 문제. 실제 SDK 타입에 맞춰 수정했다.
12. 부분 번역 실패 시 사용량이 저장되지 않던 문제. 과금 요청 전에 보수적 사용량을 기록한다.
13. DeepL 실패가 조용히 유료 LLM 호출로 이어지던 문제. 명시적 opt-in과 LLM 예산 예약을 추가했다.
14. SDK 자동 재시도, 잘린 LLM 응답. 재시도를 끄고 max_tokens 종료를 실패로 처리한다.
15. 예산 guard의 fail-open과 실제 생성에서 비용 기록 누락. 실패 시 guard 중단, 생성 호출별 로컬 보수적 예산 예약을 적용한다.
16. HTTP 무한 대기와 인증 redirect 위험. 30초 제한/redirect 차단을 추가했다.
17. 원격 저장 성공 후 로컬 이동 실패가 재발행으로 이어질 위험. 시도·receipt를 기록하고 불명확한 재실행은 차단한다.
18. 대시보드 로그인 POST가 307로 다음 페이지에도 POST를 전달하던 문제. 303으로 수정했다. 인증 없는 API는 JSON 401을 반환한다.
19. GitHub Actions 사용자 입력을 shell 문자열에 직접 삽입하던 문제. env와 인자 배열을 사용한다.
20. 외부 도구가 생성한 HTML의 실행 코드/위험한 URL. HTML 정제 후 JSON-LD만 안전하게 직렬화해 보존한다.
21. npm 취약점. SDK, DeepL 전이 의존성, CSV parser, sanitizer, Next.js/PostCSS 및 esbuild 수정 버전을 반영했다.

## 별도 확인 사항

- 기존 aside 프롬프트의 과거 루틴 메모리 참조를 발견했다. 기존 RUNBOOK 상단에 새 브릿지 절차와 현행 루틴 메모리 우선 규칙을 추가하고 원본 파일에서 확인했다.
- aside 앱은 실행 중이고 해당 chat을 표시하고 있다. 사용자가 창을 직접 활성화한 뒤에도 OS가 `window_not_focused`를 반환해 루틴 설정 클릭은 완료하지 못했다. 대신 매번 읽는 RUNBOOK을 수정해 파일 경로로 브릿지를 연결했다. 루틴 DB는 직접 수정하지 않았다.
- aside DB next_run_at은 2026-10-02 10:00 KST로 남아 있어 10월 5일 시점 예약 진행을 확정할 수 없다. 앱에서 다음 실행시각을 확인해야 한다.
- Blogger의 맞춤 퍼머링크 리셋, 저장 후 본문 갱신 누락, AdSense 위젯에 따른 hreflang 테마 저장 실패가 기존 운영 기록에 있다. 새 bridge는 API가 반환한 실제 결과/재조회 확인을 전제로 하며, 테마나 AdSense 설정은 이번 코드 점검에서 수정하지 않았다.
- Korea Decode `Admin full access` RLS가 authenticated 전체에 USING/WITH CHECK true다. 사용자가 현재 정책 유지를 명시적으로 선택해 변경하지 않았다. 일반 로그인 사용자도 수정 가능한 현재 설정은 그대로다.
- Blogger API 임시보관 테스트는 OAuth 인증 미설정으로 미실행. 기존 aside browser 경로가 기본이다.
